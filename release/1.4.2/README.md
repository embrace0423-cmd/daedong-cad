# 대동 CAD 1.4.2 받은 묶음 (참고 보관)

1.4.2는 대표님 PC의 ChatGPT(Codex) 작업 환경에서 만든 판입니다. 1.4.1에서 열지 않던 **미터(m) 단위 표기 DXF**를 열 수 있게 고쳤습니다. 2026-11-23 대표님이 `DaedongCAD-QC-Claude-Development-20261123.zip`(1,241,079바이트, SHA-256 `6630ffaa6f3907fc95c164c033b3f43f5a8f45f8920da95c5e3ce92084663f59`)을 이 세션에 올려 주셔서 옮겨 왔습니다.

## 받은 것과 확인한 것

- 묶음 안의 파일 230개 모두 크기와 SHA-256이 `MANIFEST.json`과 일치했습니다. 빠진 파일은 없었고, 목록에 없는 파일은 `MANIFEST.json` 자신뿐이었습니다.
- 받은 스크립트(`.py`·`.ps1`)는 실행하지 않았습니다.
- 바뀐 곳은 미터 DXF 열기뿐입니다(`meter-fix.diff`). 받은 1.4.2 화면을 같은 묶음 안의 1.4.1 참고본과 비교한 변경과, 이 저장소에서 다시 만든 `dist/daedong-cad.html`의 변경이 같습니다. 다른 점은 한 파일판에 `safety.js`를 넣었다는 것뿐입니다. `desktop/preload.js`와 `desktop/atomic-store.cjs`는 1.4.1과 같았습니다.
- 클린룸: 바뀐 코드는 단위 질문과 1,000배 변환뿐이고, 다른 CAD에서 가져온 것은 없습니다. 빌드 기록의 `.build-tools/rea/` 폴더는 대표님 PC에 있는 Node 실행 파일의 위치일 뿐이고, 이 판에 역분석 결과는 쓰지 않았습니다.

## 바뀐 동작

DXF의 단위 코드가 6(m)이면 열기 전에 묻습니다.

| 고르는 것 | 하는 일 | 언제 |
|---|---|---|
| **mm로 읽기 (좌표 유지)** | 좌표를 그대로 둡니다. 1,000은 1,000mm입니다 | 실제로는 mm 도면인데 단위만 m으로 적힌 경우(ezdxf 등의 기본값) |
| **m → mm 변환 (×1,000)** | 길이를 1,000배로 바꿉니다. 1은 1,000mm가 됩니다 | 정말 미터로 그린 도면 |
| 취소 (기본) | 열지 않고 지금 도면을 그대로 둡니다 | 단위를 모를 때. 원래 프로그램에서 확인 |

데스크톱은 단추 세 개짜리 창, 브라우저판은 확인 창 두 번(①mm로 읽을지 → 아니면 ②1,000배로 바꿀지)으로 묻습니다. mm(4)·인치(1)·단위 없음(0)은 1.4.1과 같고, 그 밖의 코드(예: 2 = 피트)는 여전히 열지 않습니다.

## PC에서 확인된 것 (받은 기록의 요지)

- **일반 계정**(대표님 Windows 로그인)에서 정식 설치된 1.4.2로 미터 표기 DXF를 열고 'mm로 읽기'를 고르자, 네 변이 각각 1,000mm로 읽혔습니다(2026-11-14).
- **pathfix1 설치기**: 새 폴더에 설치하면 종료 코드 10으로 실패하던 문제를 고쳤습니다. 없는 폴더 경로를 NSIS가 빈 문자열로 바꾸던 것이 원인이었습니다(`installer-pathfix.diff`). 경로 검사 10건과 설치·거부·제거 9건이 통과했고, 내부 검토 판정도 통과입니다. 설치기 SHA-256은 `9911b8d5d915eff4404b6803d2311a0272ae6bf24a8e81e50dd22640a05bc293`입니다. 판정 범위는 설치기까지입니다.
- 2026-11-14 업데이트 직후에 'DaedongCAD.exe 응용 프로그램 오류' 창이 한 번 떴습니다(예외 코드 0x80000003). 원인과 문제의 프로세스는 밝혀지지 않았고, 이벤트 기록이나 충돌 덤프도 없었습니다. 그 뒤 정상 실행은 위처럼 확인했습니다 [확인 필요].

## 아직 끝나지 않은 일 (보류)

- **제한 계정 실행**: Codex의 제한(샌드박스) 계정에서는 1.4.2가 시작되지 않습니다. Winsock 초기화가 레지스트리 접근을 거부당해 10107 오류가 납니다. 대표님이 평소 쓰시는 일반 계정과는 관계가 없고, 자동 시험 환경의 문제입니다.
- 이것을 풀려고 Electron 44.10.0을 고쳐(필요할 때만 Winsock 초기화, ICU 내장) 다시 빌드하던 중이었는데, 2026-11-18 증분 빌드가 29,346단계 중 4,234단계에서 멈췄습니다. 새 `electron.exe`는 아직 없습니다.
- 받은 안내의 중단 조건: **새 워크스테이션 설치 뒤 대표님이 다시 시작하라고 하실 때까지 빌드와 실제 PC 시험을 보류**합니다. 이 저장소에서도 Electron 데스크톱 시험(`test/desktop.js`)과 Windows 설치 파일 만들기는 이번에 하지 않았습니다.
- 다시 시작하면: 제한 계정으로 `Restricted-1000mm.dxf`를 열고 'mm로 읽기'를 고른 뒤, 앱에서 저장한 파일의 네 변이 각각 1,000mm인지 확인하고 완료로 기록합니다(받은 `README.ko.md` 6단계).
